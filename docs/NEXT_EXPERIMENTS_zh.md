# 下一阶段：固定证据抗立场干扰，同时保留有效证据更新

状态为设计提案。先核验可用的训练与推理产物，复用已完成且能追溯的实验。

## 第 0 阶段：整理已有证据

先在服务器用新增 inventory 入口登记现有基座、每种子 adapter、训练配置、日志、数据划分和翻转输出。
核对训练到底更新全量参数还是 LoRA、DPO reference 是谁、tokenizer/chat template、base revision、
实际种子和训练数据哈希。没有来源的字段标 unknown，不能推断。
核对三个种子均训练完成，原翻转是否固定立场、翻转是否同时改变正确目标，以及是否在训练中见过测试模板。
已有测试只作探索分析，不再作为新假设的独立确认集。

## 第 1 阶段：不重训的交叉干预评估

复用现有模型和 adapters，顺序加载以适配单卡 RTX 5090；所有加载显式 local_files_only=True，
设置 HF_HUB_OFFLINE=1、TRANSFORMERS_OFFLINE=1；缺失本地资产即失败，不能自动下载。
在接入真实训练代码前先确认当前 torch/CUDA、PEFT 与 adapter 的兼容性，不指定覆盖安装版本。
训练入口与推理适配器待资产核验后接入，本 PR 不提供未经核验的模型执行命令。

每个源情境交叉：相反立场/无立场 × 原证据/反事实证据 × 原模板/保义改写。
每个证据水平都有两个相反立场；每个固定立场都有原证据与反事实证据。
新增反事实必须由公共证据计算目标，不能只换选项字母。另设随机选项顺序控制，记录完整映射。
比较 base、Stance-DPO、Evidence-DPO，使用所有实际训练种子；加入 evidence-first prompting、
开发集拟合的简单收缩，以及任务适用的公共证据求解器。所有方法共享证据、生成预算与解析规则。
CAEA 修复若纳入，使用同一审计器的 audit-only；标明完全修复与 audit-only 相同报告风险的恒等关系。

先用 24 个独立情境验证流程。按源问题与模板族隔离开发和正式情境，并检查与原始训练材料的重合。根据试跑估计的方差和预设最小效应决定正式样本量。
若服务器已有相同设计的独立数据，先审查可复用性，不要求机械生成重复数据。

## 第 2 阶段：冻结与统计

主问题：Evidence-DPO 相比 Stance-DPO，是否降低固定证据的立场差，同时不损害新证据更新？
主要指标：配对立场差、目标概率平方误差、翻转更新误差、方向准确率；同时报告解析失败与拒答。
保留全部失败，冻结最坏损失计分与条件指标，不能只汇报有效回答。
分别报告每个训练种子，再报告种子间变异；三种子不冒充大量独立训练重复。
在相同源 ID 上做配对比较，按源情境 cluster bootstrap，重采样时一起保留所有方法、种子和干预。
先对种子求平均再重采样源情境所得区间只表达给定三种子的测试不确定性；训练随机性另行报告。
冻结主要比较与 Holm 多重校正规则；在开发集确定更新质量非劣界值，不用“不显著”替代非劣。
记录协议哈希、代码版本、数据哈希、模型/adapter 来源、token 和耗时/峰值显存；冻结后测试仅跑一次。

## 第 3 阶段：迁移与决策

先做模板族外迁移，再选一个已有本地、可程序核验的证据任务。第二模型家族只有本地已存在且资源允许才纳入。
若只压低立场差却抑制合理更新，报告失败边界；若有稳定提升，再考虑针对证据使用的消融训练。
不因当前 GPU 已就绪而自动扩大训练或重新下载模型。任何新增训练须另存配置与输出目录，保留全部已有实验。
